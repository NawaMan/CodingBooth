# Codex Example (token login)

This example is a minimal booth that has the [OpenAI Codex CLI](https://developers.openai.com/codex/cli) preinstalled and logs in with a token or API key you pass in. The booth never sees your host's Codex login files. No `npm install -g`, no version wrangling: Node.js and the Codex CLI are ready the moment the booth launches, in a clean, disposable sandbox isolated from the rest of your system.

Use this example when the host has no `codex` login to share (CI, a server), or when you want the booth to hold only something you can revoke. To reuse the host's `codex` login instead, see [codex-example](../codex-example/).

**Stack:** Node.js, Codex CLI

## Quick start

```bash
# 1. Launch the booth
cd examples/workspaces/codex-token-example
booth

# 2. Inside the booth — start a Codex session (the booth is its sandbox, see below)
codex --sandbox danger-full-access
```

### Get a token or key and pass it to the booth

This booth uses the `token-credential` extension: Codex logs in from an environment variable
instead of a host login. `.booth/config.toml` forwards two into the container:

```toml
run-args = [
    "-e", "CODEX_ACCESS_TOKEN=${CODEX_ACCESS_TOKEN}",
    "-e", "CODEX_API_KEY=${CODEX_API_KEY}"
]
```

`${...}` is expanded **on the host** when the booth starts, so the variable must exist there first.
Set **one** of them:

| Variable | What it is | Billed to | Who can get one |
|----------|------------|-----------|-----------------|
| `CODEX_ACCESS_TOKEN` | A Codex access token | Your ChatGPT workspace plan | ChatGPT Business and Enterprise workspaces only, when an admin allows members to create them. See OpenAI's [access tokens guide](https://learn.chatgpt.com/docs/enterprise/access-tokens); the token is shown once. |
| `CODEX_API_KEY` | An OpenAI platform API key (`sk-...`) | Per use, at API rates | Anyone with an OpenAI platform account: [platform.openai.com/api-keys](https://platform.openai.com/api-keys) |

A ChatGPT Plus or Pro login has no token form: it only exists as `~/.codex/auth.json`, which is
what [codex-example](../codex-example/) mounts.

1. **Make it available to the booth**, either way:
   - Export it in the shell that starts the booth:
     ```bash
     export CODEX_API_KEY=sk-...          # or CODEX_ACCESS_TOKEN=...
     ./booth
     ```
   - Or put the line `CODEX_API_KEY=sk-...` in `.booth/.env` (gitignored; booth refuses to start if
     it is not). Values there are also expanded on the host, so `CODEX_API_KEY=$CODEX_API_KEY`
     passes through your host variable.
2. **Check it arrived** (inside the booth):
   `[ -n "$CODEX_ACCESS_TOKEN$CODEX_API_KEY" ] && echo ok`. If empty, the variable was not set on the
   host when the booth started. Set it and start a fresh booth.

Codex reads `CODEX_ACCESS_TOKEN` in every mode, but reads `CODEX_API_KEY` from the environment
only in `codex exec` (which `just ask` uses). For an interactive `codex` session with an API key,
log in once inside the booth: `printenv CODEX_API_KEY | codex login --with-api-key`. The settings
cache keeps that login across restarts. `OPENAI_API_KEY` is not read from the environment at all.

Never put the token or key in `config.toml`, the Justfile or any committed file.

### Run it

```bash
just --list
just version                 # codex --version
just codex                   # an interactive Codex session in the booth
just ask                     # one non-interactive task via scripts/ask-codex.sh
just ask "Summarise the Justfile"
```

`just ask` runs `scripts/ask-codex.sh`, which calls `codex exec`, prints only the final answer and
exits. It stops with a hint if neither variable is set.

Inside a booth, Codex's own sandbox cannot start, so `just ask` runs with
`--sandbox danger-full-access` and the booth is the sandbox instead. The same is why there is no
`just vet` here. [codex-example](../codex-example/#the-booth-is-codexs-sandbox) explains both.

## What's included

| Component      | Details |
|----------------|---------|
| Tool           | `codex` CLI (OpenAI's terminal coding agent), on Node.js |
| Login          | `token-credential`: forwards `CODEX_ACCESS_TOKEN` and `CODEX_API_KEY` from the host; `~credential` drops the host-file mount |
| Settings cache | `settings-cache`: `~/.codex` in the booth is a cache folder, so settings and sessions survive a booth restart |
| `just ask`     | `scripts/ask-codex.sh`: one `codex exec` task, final answer only |

Generated by
`booth config --select 'codex+settings-cache+token-credential~credential~vscode-ext/nodejs~npmrc~vscode-ext'`.
`token-credential` forwards the variables, `~credential` turns off the default host-login mount,
`~vscode-ext` drops the VS Code extensions, and `~npmrc` keeps your host's `~/.npmrc` out of the
booth.
