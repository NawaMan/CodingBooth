# Oh My Pi Example (token login)

This example is a minimal booth that has [Oh My Pi](https://omp.sh) (`omp`, a terminal coding agent for 40+ model providers) preinstalled and logs in with a Claude subscription token. You create a long-lived token on the host with `claude setup-token` and pass it into the booth as `ANTHROPIC_OAUTH_TOKEN`; omp then runs Anthropic's models on your Claude subscription. The booth never sees your host's omp login files. No installer script, no version wrangling: `omp` is ready the moment the booth launches, in a clean, disposable sandbox isolated from the rest of your system.

Use this example when the host has no `omp` login to share (CI, a server), or when you want the booth to hold only a token you can revoke. To reuse the host's `omp` login instead, see [omp-example](../omp-example/). It is the same token [claude-token-example](../claude-token-example/) uses, so one token serves both.

**Stack:** Oh My Pi (`omp`)

## Quick start

```bash
# 1. Launch the booth
cd examples/workspaces/omp-token-example
booth

# 2. Inside the booth — start an omp session
omp
```

### Get a token and pass it to the booth

This booth uses the `token-credential` extension: omp logs in with a long-lived
`ANTHROPIC_OAUTH_TOKEN` instead of a host login. `.booth/config.toml` forwards it into the container:

```toml
run-args = ["-e", "ANTHROPIC_OAUTH_TOKEN=${ANTHROPIC_OAUTH_TOKEN}"]
```

`${...}` is expanded **on the host** when the booth starts, so the variable must exist there first.

1. **Create the token** (needs a Claude Pro/Max/Team/Enterprise subscription, not API billing). On
   the host, with [Claude Code](https://docs.claude.com/en/docs/claude-code) installed:
   ```bash
   claude setup-token
   ```
   Log in in the browser; it prints a token (`sk-ant-oat01-...`). Copy it, it is shown once.
2. **Make it available to the booth**, either way:
   - Export it in the shell that starts the booth:
     ```bash
     export ANTHROPIC_OAUTH_TOKEN=sk-ant-oat01-...
     ./booth
     ```
   - Or put a line `ANTHROPIC_OAUTH_TOKEN=sk-ant-oat01-...` in `.booth/.env`
     (gitignored; booth refuses to start if it is not). Values there are also expanded on the host,
     so `ANTHROPIC_OAUTH_TOKEN=$CLAUDE_CODE_OAUTH_TOKEN` reuses a token you already export for
     Claude Code.
3. **Check it arrived** (inside the booth): `[ -n "$ANTHROPIC_OAUTH_TOKEN" ] && echo ok`.
   If empty, the variable was not set on the host when the booth started. Set it and start a fresh booth.

omp reads `ANTHROPIC_OAUTH_TOKEN` ahead of `ANTHROPIC_API_KEY`. Other providers work the same way
with their own variable (`OPENAI_API_KEY`, `XAI_API_KEY`, `GEMINI_API_KEY`, ...; `omp --help` lists
them all): forward one with `booth config --env NAME=\${NAME}` and set it on the host.

Never put the token in `config.toml`, the Justfile or any committed file.

### Run it

```bash
just --list
just version                 # omp --version
just omp                     # an interactive omp session in the booth
just ask                     # one non-interactive task via scripts/ask-omp.sh
just ask "Summarise the Justfile"
just vet https://github.com/jonschlinkert/is-odd   # vet a repo -> reports/jonschlinkert-is-odd.md
```

`just ask` runs `scripts/ask-omp.sh`, which calls `omp -p` with read-only tools, prints the answer
and exits. It stops with a hint if the token is missing.

`just vet` clones a repository into the booth's `/tmp` and has omp vet it with only read tools,
with the repository's own extensions, MCP servers, language servers, skills and rules turned off.
[omp-example](../omp-example/#vet-a-repo-before-you-run-it) explains what each flag stops.

## What's included

| Component      | Details |
|----------------|---------|
| Tool           | `omp` (Oh My Pi terminal coding agent) |
| Login          | `token-credential`: forwards `ANTHROPIC_OAUTH_TOKEN` from the host; `~credential` drops the host-file mount |
| Settings cache | `settings-cache`: `~/.omp` in the booth is a cache folder, so settings and sessions survive a booth restart |
| `just ask`     | `scripts/ask-omp.sh`: one `omp -p` task with read-only tools |
| `just vet`     | `scripts/vet-repo.sh`: clones a repo into the booth's `/tmp` and has omp vet it with only `read`, `grep` and `glob`; writes `reports/<owner>-<repo>.md` |

Generated by `booth config --select 'oh-my-pi+settings-cache+token-credential~credential'`.
`token-credential` forwards the token and `~credential` turns off the default host-login mount. See
"Get a token" above for how omp gets its login.
