# Codex Example

This example is a minimal booth that has the [OpenAI Codex CLI](https://developers.openai.com/codex/cli) preinstalled and reuses the `codex` login you already have on the host. Log in once on the host and every booth from this folder is logged in too. No `npm install -g`, no version wrangling: Node.js and the Codex CLI are ready the moment the booth launches, in a clean, disposable sandbox isolated from the rest of your system.

To log in with a token or API key you pass in instead (no host login needed), see [codex-token-example](../codex-token-example/).

The same booth for other agents: [claude-example](../claude-example/), [grok-example](../grok-example/), [omp-example](../omp-example/).

**Stack:** Node.js, Codex CLI

## Quick start

```bash
# 1. Launch the booth
cd examples/workspaces/codex-example
booth

# 2. Inside the booth — start a Codex session (the booth is its sandbox, see below)
codex --sandbox danger-full-access
```

### Log in on the host first

This booth uses the `credential` extension (selected by default with `codex`). It mounts your
host's Codex login into the booth, read-only. `.booth/config.toml` has:

```toml
run-args = [
    "-v", "~/.codex/auth.json:/etc/cb-home-seed/.codex/auth.json:ro",
    "-v", "~/.codex/config.toml:/etc/cb-home-seed/.codex/config.toml:ro"
]
```

- `~/.codex/auth.json` is your login, and `~/.codex/config.toml` your settings. Both are copied
  into the booth's home once. After that, the booth keeps its own copy in its settings cache (see
  below), so changes made inside the booth stay in the booth.
- The rest of `~/.codex` (sessions, history, logs) stays on the host. It is a transcript of every
  Codex conversation you have had there.

1. **Log in on the host** (a ChatGPT plan, or an API key):
   ```bash
   codex login
   ```
   Both files must exist before the booth starts. If one is missing, booth skips that mount
   (`Skipping volume mount: host path does not exist`), and Codex in the booth is not logged in.
2. **Start the booth:** `./booth`.
3. **Check the login arrived** (inside the booth): `codex login status`.

The login is copied only once, into the settings cache. If you log in again on the host, delete
`.booth/cache/home/coder/.codex/auth.json` so the next booth picks up the new one.

### Run it

```bash
just --list
just version                 # codex --version
just codex                   # an interactive Codex session in the booth
just ask                     # one non-interactive task via scripts/ask-codex.sh
just ask "Summarise the Justfile"
```

`just ask` runs `scripts/ask-codex.sh`, which calls `codex exec`, prints only the final answer and
exits. It stops with a hint if no login is found.

### Example

Run from the host, `just ask` starts the booth, asks Codex, prints the answer, and stops the booth
again. `2>/dev/null` hides the booth's start/stop messages, so only the answer shows:

```console
$ just ask 'What is the day after Monday' 2>/dev/null
Tuesday.
```

## The booth is Codex's sandbox

On a normal machine, Codex runs its shell commands in a sandbox of its own (`--sandbox read-only`
or `workspace-write`). That sandbox is built from Linux namespaces (bubblewrap), which an ordinary
Docker container does not provide, so inside a booth it cannot start. With it on, Codex cannot even
run `ls`: every command fails with `sandbox could not create a namespace`.

So `scripts/ask-codex.sh` runs `codex exec --sandbox danger-full-access`, and the booth is the
sandbox instead. Codex can read and write this project folder, which is mounted into the booth,
but it cannot reach the rest of your host. `just codex` starts the interactive session the same
way; if you run `codex` yourself in the booth, add `--sandbox danger-full-access`.

That is also why this example has no `just vet` (see [claude-example](../claude-example/#vet-a-repo-before-you-run-it)).
Codex reads files through its shell, so it cannot review a repository without one. In the booth
that shell is unsandboxed, and a repository that plants instructions in its files could steer
Codex into running its code, with `~/.codex/auth.json` readable and the network open. The Claude,
Grok and omp examples can turn the shell off and keep only read tools; Codex cannot.

## What's included

| Component      | Details |
|----------------|---------|
| Tool           | `codex` CLI (OpenAI's terminal coding agent), on Node.js |
| Login          | `credential`: seeds the host's `~/.codex/auth.json` and `~/.codex/config.toml` |
| Settings cache | `settings-cache`: `~/.codex` in the booth is a cache folder, so the login, settings and sessions survive a booth restart |
| `just ask`     | `scripts/ask-codex.sh`: one `codex exec` task, final answer only |

Generated by `booth config --select 'codex+settings-cache~vscode-ext/nodejs~npmrc~vscode-ext'`
(`credential` comes with `codex` by default). `~vscode-ext` drops the VS Code extensions, which a
terminal-only booth has no use for, and `~npmrc` keeps your host's `~/.npmrc`, which can hold npm
registry tokens, out of the booth.
