# booth showcase

> Browse and import booths published on CodingBooths.online.

`booth showcase` talks to the [CodingBooths.online](https://codingbooths.online) showcase API so you can discover and clone published booths without a browser.

```bash
./booth showcase list
./booth showcase import NawaMan-GMail/defaultj ./defaultj
```

## Overview

A showcase is a booth's `.booth/` configuration published at `https://<web-domain>/show/{handle}/{slug}`, pinned to an exact git commit of its source repository. `booth showcase` reads the same JSON API the website uses:

| URL | Returns |
|---|---|
| `GET /show.json` | Cross-tenant gallery of all published showcases |
| `GET /show/{handle}.json` | One tenant's published showcases |
| `GET /show/{handle}/{slug}.json` | One showcase's full detail, pinned to its published commit |

`booth showcase import` turns a detail entry into a real project: it clones the showcase's source repository at the exact published commit, then writes the showcase's own `Boothfile`/`config.toml` into `.booth/` (only if the cloned repo doesn't already commit its own — most projects gitignore `.booth/`, which is why the API bundles the rendered files directly).

## Commands

### `showcase list`

List published showcases — the cross-tenant gallery, or one tenant's showcases when a handle is given.

```bash
./booth showcase list
./booth showcase list NawaMan-GMail
```

Output:

```
HANDLE         SLUG      TITLE     VARIANT       VERSION  PUBLISHED
NawaMan-GMail  defaultj  defaultj  desktop-xfce           2026-09-12T17:27:44Z
```

### `showcase show`

Show one showcase's detail: title, variant, source repo, and rendered README.

```bash
./booth showcase show <handle>/<slug>
```

Example:

```bash
./booth showcase show NawaMan-GMail/defaultj
```

### `showcase import`

Create a new booth project from a showcase.

```bash
./booth showcase import <handle>/<slug> <path>
```

- `<handle>/<slug>` — the showcase to import (from `showcase list`)
- `<path>` — the target directory (must not already exist)

Example:

```bash
./booth showcase import NawaMan-GMail/defaultj ./defaultj
```

Output:

```
Fetching showcase NawaMan-GMail/defaultj...
Cloning https://github.com/NawaMan/DefaultJ.git (branch master) pinned to c36547d02159ac950d29640d4fac318f9bb53f80...

Showcase 'NawaMan-GMail/defaultj' ready at: ./defaultj (pinned to c36547d02159)

To get started:
  cd ./defaultj
  ./booth
```

### Flags

| Flag | Applies to | Description |
|------|------------|-------------|
| `--limit <n>` | `list` | Page size (passed through to the API) |
| `--cursor <token>` | `list` | Continuation cursor from a previous `--json` listing |
| `--version <n>` | `show`, `import` | Fetch a specific published history entry instead of the latest |
| `--json` | `list`, `show` | Print the raw API response instead of a formatted view |

## Getting Started

A typical workflow:

```bash
# 1. Browse what's published
./booth showcase list

# 2. Inspect one before committing to it
./booth showcase show NawaMan-GMail/defaultj

# 3. Import it
./booth showcase import NawaMan-GMail/defaultj ./defaultj

# 4. Enter the project and launch
cd ./defaultj
./booth
```

The commit is pinned exactly as it was when published — `git log` in the new project shows detached HEAD at that commit, not the branch tip. Since `.booth/Boothfile` and `.booth/config.toml` were written directly rather than generated by `booth config`, a later `booth config` run in that project treats them as hand-written and protects them (keep-mine / `.new`) rather than silently regenerating over them.

## Configuration

`booth showcase` talks to `https://dev.codingbooths.online` by default (the current dev host for CodingBooths.online). Override it with:

```bash
export BOOTH_SHOWCASE_URL=https://codingbooths.online
```
